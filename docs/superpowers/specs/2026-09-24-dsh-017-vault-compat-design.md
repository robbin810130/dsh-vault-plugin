# DSH 0.1.7 Vault 兼容设计

## 目标

升级本机 DeepSeek Harness 至官方 `0.1.7-rc.1`，同时恢复并验证 Vault 插件在该版本上的工作能力。最终交付包括适配代码、版本固定的本机 DSH 浏览器包补丁、Vault 插件新版本发布，以及从启动器打开到退出卸载的本机端到端验收。

## 当前情况

- Vault 当前主线为 `v0.2.7`，已有 DSH `0.1.5-rc.1` 主机兼容补丁；该补丁无法直接应用到官方 DSH `0.1.7-rc.1`。
- DSH 0.1.7 改变了插件设置机制。旧版使用的 `ctx.settings.installSection()` 和 `ctx.settingsScope.bind()` 不再适用；新机制以插件配置 schema 和 client `configForms` 为中心。
- DSH 的浏览器端没有 Vault 所需的会话访问保护和工作区行扩展接口。因此，仅迁移插件 API 不能恢复锁定会话的保护。
- 既有本机生命周期约束保持不变：DSH 不自启动常驻，只由 DeepSeek Harness.app 按需启动并在退出时回收；不得误杀未知的 3080 端口占用者。

## 设计

### 1. 版本固定的 DSH 浏览器兼容补丁

从官方 `dsh-v0.1.7-rc.1` 源码构建最小本机补丁，只补回 Vault 所需的浏览器端扩展缝隙：

- 在每条会话打开/路由入口执行访问判定；未解锁或判定失败时拒绝打开，并且不加载/渲染受保护的对话内容。
- 向会话/工作区行暴露最小扩展点，以展示 Vault 状态与锁定提示。
- 在锁定会话的视图上展示明确的拒绝状态，避免旧消息短暂闪现。
- 对相关 bundle 的源版本和校验和做严格校验。目标版本或输入哈希不符时，构建/安装必须失败，不能静默套用补丁。

补丁是本机对官方发行版的兼容层，不声称上游已提供这些 API，也不改变 DSH 服务端鉴权或磁盘加密语义。

### 2. Vault 迁移到 DSH 0.1.7 设置 API

- 将每个 Vault 插件实例的设置通过 DSH 0.1.7 插件配置 schema 表达。
- client UI 使用 `configForms` 和 `settings.plugins.tab` 注册 Vault 设置页面，依赖当前插件 entry id；配置读写遵循 DSH 的服务端 schema/表单机制。
- 明确区分可持久化 Vault 配置与运行期解锁状态。密码和解锁态不得进入普通持久化配置。
- 保留现有 Vault 密钥、绑定关系、加密记录和迁移兼容；升级不得清空或重置用户数据。

### 3. 访问保护不变量

- 锁定时，从会话列表、搜索/深链及其他会话打开入口触发访问，都不得把受保护消息内容加载或显示给 UI。
- 判定结果为拒绝、过期或异常时一律失败关闭；不能因插件未就绪而放行。
- 仅在会话成功解锁后才允许显示其受保护消息；锁定状态和 UI 标识须在会话切换、刷新及过期时一致。
- Vault 的本地保护边界须在文档中准确说明：此兼容功能属于 DSH UI 访问门禁，不等同于服务器端授权或对 DSH 数据库文件的整体加密。

## 失败处理与回滚

- 升级前记录 DSH 版本、配置/插件清单及 profile 备份；补丁仅作用于明确识别的 0.1.7-rc.1 安装。
- 安装或健康检查失败时，恢复受影响的官方 DSH 包和 profile 备份；不得清理用户数据来换取启动成功。
- 未知进程占用 3080 时停止自动启动并报告 PID/命令，不结束该进程。
- 回滚过程保留日志、补丁哈希和备份路径，便于复核。

## 验收

### 自动化

- 保持现有 Vault 单元/集成测试通过，并为 0.1.7 配置 schema、表单注册/更新和多实例配置补充测试。
- 对 DSH 补丁中每个会话入口测试允许、拒绝、异常三类结果；拒绝时断言消息 fetch/render 均未发生。
- 测试工作区行状态、会话切换、超时锁定、刷新和异常 fail-closed。
- 从官方 0.1.7-rc.1 源码重建相关 browser bundles，并验证补丁只接受目标版本与预期输入哈希。

### 本机端到端

- 安装官方 DSH 0.1.7-rc.1 与补丁版 bundle，安装候选 Vault 插件版本，启动器冷启动成功。
- 浏览器完成真实认证后，验证 Vault 设置可读写、锁定会话不可查看、解锁后可查看、页面刷新与会话切换仍正确。
- 关闭 App 后确认 guardian、DSH 服务及 3080 listener 全部退出；重复打开成功；LaunchAgent 仍保持禁用。
- 独立确认 `dsh web` 不会因启动器遗留 listener 再次触发 `EADDRINUSE`。

### 发布

- Vault 版本按仓库既有发布流程递增为 `0.2.8`（若实现内容与发行约束要求不同，实施计划阶段明确解释）。
- 发布前运行仓库规定的构建、测试、打包和兼容性验证；发布后核对 GitHub tag/release、包版本和本机已安装版本。

## 风险与边界

- DSH 是预发布版本，browser bundle 结构可能变化；版本/哈希门禁和可回滚安装是强制要求。
- 兼容补丁维护本机 fork 式差异，未来 DSH 更新必须重新核对上游并显式迁移，不自动跨版本复用。
- UI 门禁能保护应用内的访问体验，但不能防止用户直接读取 DSH 数据库或绕开 UI 的本机进程；不对其作超出实现的安全承诺。
- 真实认证、锁定/解锁和退出生命周期的本机验收分别记录；构建通过不能替代运行验收。

## 暂不包含

- 不改造 DSH 服务端权限模型或数据库格式。
- 不改变按需启动/退出回收的既有启动器策略。
- 不顺手移除其他插件或重构 Vault 无关功能。
