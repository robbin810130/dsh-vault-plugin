# DSH 保险箱页面设计审核

## 总评

- Nielsen 可用性评分：22/40，处于“方向成立，但发布前需要明显加固”的区间。
- 严重级别：P0 0 项、P1 3 项、P2 3 项。
- AI 模板化风险：轻到中度。页面克制、可信，但大阴影卡片、Inter、居中锁图标和均匀卡片权重让它略像通用安全产品模板，DSH 自身气质偏弱。
- 两份独立审核对窄屏整体滚动结论不一致；确定性浏览器测量显示宿主可纵向滚动，因此不把“页面整体不可达”列为问题。已确认的问题是：390px 宽时弹窗初始 top=686、bottom=1044，操作区落在首屏之外，且焦点仍停留在外部按钮。

## 认知负荷

- 结论：中等，8 项检查中 2 项失败。
- 行菜单一次展示 5 个等权动作，主次与危险程度不够分明。
- 密码组仅给“1 个项目 · 3 个对话”之类计数，用户必须记住组内成员和继承关系。

## 情绪旅程

- 锁定态安静、可信，紫色锁标识和范围说明能快速建立安全预期。
- 解锁弹窗是最强的信任节点：清楚说明会同时解锁哪些内容、15 分钟自动锁定，以及密码仅发给本机 DSH Host。
- 最大信任断点是没有错误与恢复路径。用户无法预判输错密码、Host 不可用或恢复密钥丢失时会发生什么。
- 已解锁状态的绿色标识和剩余时间有帮助，但缺少明确的“解锁成功”反馈，倒计时也可能制造不必要的紧迫感。
- “恢复密钥只显示一次”会带来焦虑，当前页面没有同步解释丢失后的后果与补救能力。

## 做得好的地方

1. 解锁范围披露清楚：明确说明会同时解锁 3 个继承项目密码的对话。
2. 状态语言连续：左侧锁图标、主内容锁定态、绿色已解锁状态和过期时间相互呼应。
3. 设置的信息架构符合安全产品心智模型：锁定策略、恢复密钥、密码组被合理拆分。
4. 基础无障碍结构有亮点：原生状态按钮带 aria-pressed，弹窗有 role=dialog、aria-modal 和可解析标题，设置 select 有 label，状态切换有 polite live region。

## 优先级问题

### P1 — 弹窗在窄屏首屏之外，且焦点管理失效

- 390×844 下，弹窗横向不溢出，但初始位置为 top=686、bottom=1044，操作区不在首屏；页面不会自动滚动到弹窗。
- 打开后焦点仍在外部“解锁弹窗”预览按钮，没有自动进入密码框；Esc 不关闭；源码没有 focus trap 与关闭后焦点归还。
- 影响：键盘用户、屏幕阅读器用户和窄屏用户可能不知道弹窗已经打开，或找不到操作区。

### P1 — 核心导航不是键盘可达控件，触控目标偏小

- 项目/对话行和“设置”入口是带 click handler 的 div，没有 button/link 语义、role 或 tabindex。
- 行尾省略号按钮为 26×26px，明显低于常见的 44×44px 触控目标。
- 影响：键盘用户无法进入保险箱内容；移动端误触风险高。

### P1 — 安全流程只有成功路径

- 空密码可以直接提交；没有错误密码、加载、重试、连续失败锁定、DSH Host 不可用、会话过期、跨标签页同步等状态。
- “解除保护”是破坏性操作，但没有二次确认、影响范围或回滚说明。
- 恢复密钥只强调“显示一次”，没有丢失后的实际后果和替代路径。
- 影响：在最需要信任和可恢复性的安全场景里，用户会遇到静默失败或不可逆操作。

### P2 — 密码组范围仍依赖记忆

- 密码组只显示数量，未展示代表性成员、继承/独立状态和单项覆盖规则。
- 建议在管理入口前直接预览 2–3 个成员，并显式标记“继承项目密码”或“独立密码”。

### P2 — 信息层级和文案还不够精确

- “设置 · 插件 · 插件配置”重复“插件”；“打开密码”不如“保险箱密码”或“解锁密码”自然。
- 已锁定上下文仍显示“全部锁定”，用户不清楚它针对哪些其他已解锁项。
- 搜索只有装饰性的 `⌕`，没有标签、按钮语义或实际入口。

### P2 — 视觉可信，但略显通用模板

- app-window 与 dialog 同时使用细边框和大面积远投影，形成常见的“悬浮样机卡片”效果。
- Inter、居中锁图标空状态、淡紫安全色与等权设置卡片都较通用，DSH 产品身份较弱。
- 恢复密钥这种高风险能力与普通设置卡片同权，重要性没有被视觉层级承载。

## 三类用户视角

### Sam（无障碍）

- 项目、对话和设置入口不可聚焦。
- 弹窗缺少初始焦点、Esc、焦点陷阱与焦点归还。
- 26px 菜单按钮过小。
- 浅色模式下 muted 文本和绿色状态色接近 WCAG AA 临界值，应使用真实字体大小和渲染结果复测。

### Riley（边界情况）

- 缺少空输入、错误密码、Host 失败、页面刷新、跨标签页、到期自动锁定等状态。
- 未表达改密和解除保护会影响项目、对话还是整个密码组。
- 长项目名、上千条对话、大型密码组和恢复密钥丢失尚未设计。

### Alex（效率）

- 关键动作只藏在省略号菜单里。
- 没有“仅锁定当前项”、批量分组、过期时间总览或快捷命令。
- 弹窗不能用 Esc 取消，打断键盘工作流。

## 次要问题

- 解锁后侧栏出现重复的“供应商风险清单”，可能让用户误判当前项。
- 顶部四个状态切换器是评审脚手架，生产页面应完全移除。
- 缺少 disabled、loading、error、success 等组件状态。
- 行菜单 5 个动作等权，建议把危险操作与日常操作分组。
- 大阴影在深色 DSH 宿主中更像独立 mockup，而非原生插件界面。

## 待确认问题

1. 输入一次密码后，默认应解锁当前对话、整个项目，还是整个密码组？
2. 手机端应默认先展示对话内容，并把侧栏收进抽屉吗？
3. 恢复密钥丢失后，真实产品是否存在重置或重新加密路径？
4. 自动锁定可靠时，“全部锁定”是否还需要在每个标题栏持续出现？
5. 密码组是否可以直接展示 2–3 个成员名称，减少用户记忆负担？
